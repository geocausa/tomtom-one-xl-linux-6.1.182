# TomTom ONE XL UI V3 — final hardware-polished shell (2026-10-14)

## Scope

This pass changes launcher presentation and touch target geometry only. It deliberately does **not** change the accepted Bluetooth/audio pipeline, ALSA buffering, BlueALSA settings, kernel drivers, or the existing touch-down activation model.

Design direction: retain the dark low-cost framebuffer shell, but borrow the original TomTom menu discipline: icon-first navigation, large targets, one primary label, one quiet subtitle, generous spacing, and minimal diagnostic text on normal user screens.

## Accepted hardware UI

Home remains a four-tile layout:

- CALIBRATE — Touch setup
- TOOLS — System & remote
- EXPLORER — Files & storage
- BLUETOOTH — Wireless audio

TOOLS contains Terminal and USB + SSH. Bluetooth presents product-facing pairing/status/actions rather than codec/transport telemetry. Explorer uses DEVICE / SD CARD / UP navigation and large file/folder rows. Calibration keeps the existing sampling and `pointercal` format, with only its visuals restyled.

Touch activation remains on touch-down because it is reliable on the physical resistive panel. No release-to-activate experiment is required for this accepted design.

## TomTom TTBL signing

Use the existing OpenTom `mkttimage` implementation. It signs each section as MD5 followed by Blowfish using the recovered TomTom firmware key. This tool reproduced the previous #176 production TTBL byte-for-byte before it was trusted for V3.
